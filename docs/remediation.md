# P1/P2 修复与升级说明

本次修复覆盖历史工具响应闭环、混合工具调用失败、大整数恢复、MongoDB 大回执/检查点、任务维护退出、SSE 空轮询、增量写入、上下文压缩和恢复扫描。接口权限策略保持原样；所有普通读取、维护恢复和不可变载荷查询仍使用完整租户与用户作用域。

## 执行与持久化

- 已结束 Run 留下的工具调用，在新模型输入中获得本地派生响应，说明本地结束状态和远端结果未知。原始历史不改写，不伪造远端成功、失败或取消。
- 同一模型响应中部分调用返回任务、部分调用结果不确定时，先保存全部已知句柄和失败检查点，再将 Run 结算为失败。崩溃恢复先补齐句柄；失败标记优先于等待状态，不重执行工具。
- 暂停检查点写入 `cagent.adk.tools.v2`，继续读取 v1。SDK 状态和动态 JSON 解码使用 `UseNumber`，恢复后保留大整数精度。
- 回执版本 1 内联小结果；版本 2 引用不可变完整提交结果。超过 4 MiB 的检查点也使用不可变载荷。块大小为 4 MiB，单个逻辑载荷上限 64 MiB，读取校验长度、分块数与 SHA-256。块和引用同事务写入，回滚不留孤儿；不得对仍被回执/检查点引用的块设置 TTL。
- 文本增量在 75 ms 或 8 KiB 边界合并提交。完整消息、工具输出、检查点和终态之前先刷出增量，保留顺序及写入失败背压。客户端按 sequence 重放，不依赖一个模型 token 对应一条事件。

## 任务维护退出

`status` 仍表示提供方状态；`maintenance` 表示本地维护状态：`active`、`quarantined`、`settled`。隔离保留句柄和真实远端状态，退出自动恢复扫描。活动 Run 的必要任务被隔离时，Run 失败并释放会话占用，失败原因为 `task_maintenance_quarantined`，远端结果标记为未知。

正常观察会记录 `last_contact_at`，即使提供方快照没有变化；`LastObservedAt` 的原有“业务内容变化”含义保持不变。连续观察失败使用持久化指数退避，退出期限优先于退避，并限制正在进行的观察；新取消意图立即安排观察。取消尝试次数及安全原因单独保存，不把取消请求成功当成远端已取消。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `CAGENT_MAINTENANCE_WORKERS` | 32 | 同时维护的 Run 上限，与生成容量独立 |
| `CAGENT_MAINTENANCE_CANCEL_GRACE` | 5m | 首次取消意图后的自动维护宽限期 |
| `CAGENT_MAINTENANCE_DETACHED_GRACE` | 24h | 本地 Run 结束后的自动观察宽限期 |
| `CAGENT_MAINTENANCE_OUTAGE_GRACE` | 30m | 连续失联宽限期 |
| `CAGENT_MAINTENANCE_INTERACTION_GRACE` | 24h | input/auth required 交互停滞宽限期 |
| `CAGENT_MAINTENANCE_MAX_BACKOFF` | 5m | 观察失败退避上限 |

这些期限限制本地维护，不限制远端任务寿命。工具注册表缺失也按观察不可用处理，既有任务仍遵循本地退出期限。等待没有独立 Run goroutine，也不占用 `CAGENT_CAPACITY_RUNS` 的生成槽位。单实例总执行与观察数量有界，本地至多保存 4096 个到期提示；启动装配的持久恢复扫描负责重启和提示溢出后的接管。

`POST /api/v1/tasks/:taskID/resume-observation` 在原用户作用域内恢复隔离任务的观察，返回 202。仅接受本地任务 ID，继续使用同一远端句柄，保留取消意图并重新给予本地观察宽限期。该操作不重开终态 Run，也不重新调用工具。任务 GET 增加维护状态、原因、最近联系、下次观察和取消诊断字段，仍不返回远端句柄或连接配置。

## SSE 和恢复扫描

同一个数据库对象共享按 Scope+Run 分组的通知中心，本机提交立即唤醒订阅，一个数据库 Change Stream 处理跨实例通知。通知仅为提示，事件正文和终态水位仍由每个订阅自己的作用域及持久游标读取。先登记通知再读取，关闭切换窗口；慢客户端保留自己的游标，不积累广播队列。

每 3 秒只对有订阅的 Run 查询一次水位元数据，无快照事务。多个订阅共享后备检查；水位不变时不重新读取事件页。Change Stream 中断时重新同步并重连，后备检查覆盖缺失通知；MongoDB Change Stream token 不作为 SSE 游标。生产多节点故障和容量目标仍需部署验收。

Run 的 `recovery/next_action_at` 为事务维护的扫描投影。全局 `recovery_due` 部分索引按到期时间、租户、用户、Run ID 分页；有效租约移后候选到期时间。扫描仍使用数据库时间并检查租约，实际执行再次通过 Fence/CAS 授权。

## 上下文

新摘要记录已验证前缀水位；后续准备在一致快照中读取受保护消息和新尾部，校验尾部连续性及会话版本。旧快照没有验证标记时继续完整读取。兼容摘要只总结旧摘要和新增前缀；策略变化从原始历史重建。摘要输入超预算时按消息分段，每次准备最多 32 次受限摘要尝试；网络/模型错误不自动重试。单条消息仍无法装入摘要窗口时明确报预算错误。

`CAGENT_CONTEXT_ARCHIVE_COMPLETED=false` 为默认配置，保留用户原文和工具关联。显式设为 true 且启用压缩时，完整已结束轮次可由摘要表示，保留近期轮次、当前输入和系统约束；原文仍在数据库。归档策略使用独立 `/archive-v1` 策略版本。最终输入仍按实际模型计数，装不下时 Run 明确失败为 `context_budget_exceeded`，不会截断内容后调用模型。

## 升级与验收

先停止旧版本写入实例，再部署新版本。`mongodb.Open` 幂等创建新增索引并回填旧 Run 的恢复投影、旧消息的保护标记；迁移失败会阻止启动，不以全表扫描降级运行。大库应先评估迁移时间及启动超时。旧回执、内联检查点和 v1 暂停检查点可读；生成 v2 检查点或分块引用后，不支持直接回滚到不认识这些格式的旧执行器。

执行 `scripts/acceptance.ps1`，设置 `CAGENT_TEST_MONGOD` 指向 MongoDB 8.0.32 程序。覆盖真实事务、原提交重放、分块回滚、任务隔离与恢复、跨实例通知、历史配对、大整数、增量合并、增量上下文和归档边界。脚本同时执行竞态检查、vet 和构建；真实外部模型及工具 smoke 测试需要单独显式配置。
