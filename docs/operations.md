# 容量、观测与数据保留（P10.2）

本文描述已装配的单实例运行保障。MongoDB 的 Scope、事务、租约和 Fence 继续负责多实例一致性；本地容量闸门只保护当前进程，不提供集群配额或租户公平调度。增加副本会增加总容量，应由部署者按模型配额和数据库容量控制副本数。

## 容量与过载

| 环境变量 / 配置 | 默认值 | 占用范围与满载行为 |
| --- | --- | --- |
| `CAGENT_CAPACITY_RUNS` | 64 | 新 Run 在落库前预留；恢复调度也必须领取。等待工具、暂停交互和取消后的迟到结果维护仍占槽位，整个本地维护循环退出才释放 |
| `CAGENT_CAPACITY_MODELS` | 16 | 主模型和摘要模型共享；从开始调用到完整读取或提前关闭流一直占用。满载不发送模型请求、不自动重试 |
| `CAGENT_CAPACITY_OBSERVATIONS` | 32 | 所有 Run 的后台任务观察共享；包含取消请求、订阅、查询和本次观察退避。另保留每 Run 每页 32 个任务、最多 8 个观察请求的限制 |
| `CAGENT_HTTP_MAX_SUBSCRIPTIONS` | 256 | 每个 HTTP 服务的 SSE 连接共享，在检查游标和写流头前领取；退出且 Follow 完成后释放 |
| 工具清单 `max_input_bytes` / `max_output_bytes` | 各 1 MiB | Catalog 统一限制本地与协议工具输入、即时结果、任务结果和进度；结果超限没有 artifact 后端时明确拒绝 |

四个环境变量均为 1–100000 的整数；显式空值、零、负数和超范围值拒绝启动。工具清单输出限制为 256 字节–8 MiB；MCP/A2A HTTP 响应（含订阅流）另有 16 MiB 总读取上限和超时。本地工具必须遵守 context，不通过遗留 goroutine 伪装超时；可信本地扩展自身的分配仍由扩展作者负责。

新运行和 SSE 满载返回 HTTP `503`、`error.code=overloaded`、`Retry-After: 1`。新运行拒绝不会写消息、Run 或会话占用。非空幂等键在满载时仍可只读找回相同输入的已提交 Run，不同输入返回冲突。该查询不会创建新 Run。事务后客户端断开不撤回已接纳工作；关闭窗口内未启动的 queued Run 由下一实例恢复。

恢复候选满载时不创建 goroutine 或内存队列，留待后续扫描；下次成功调度仍须取得数据库租约并重读。模型容量拒绝会通过 `ErrOverloaded` 传播；如果没有安全摘要回退，或主模型被拒绝，运行按现有失败流程保存 `run.failed`（reason 为 `overloaded`），不盲目重放此前的外部副作用。单次观察满载只记录观察中断，按原句柄继续轮询，不伪造远端终态。

SSE 使用无缓冲交付通道、分页读取、单 writer 和逐次写/flush 截止时间；没有随消费者延迟增加的消息队列。慢消费者或断连只结束订阅；客户端使用最后消费的 `Last-Event-ID` 重连。页缓存、连接及观察缓冲均受上述上限约束。远端任务寿命不受 `ObservationTimeout` 限制，长时间暂停会占用本实例运行容量；需要扩容或由用户明确取消，不自动把任务判为失败。

## 指标与追踪

默认启用以下无需认证的运维接口：

- `GET /debug/metrics`：Prometheus 文本格式。
- `GET /debug/traces`：最近最多 256 条已结束 span 的 JSON 快照。

两者均无需认证。请求响应头包含服务生成的 `X-Trace-ID`，不采信客户端自报 trace ID。

| 指标 | 语义 |
| --- | --- |
| `cagent_operations_total` | 已结束操作数，包括失败 |
| `cagent_failures_total` | 返回错误的操作数；HTTP 按最终状态码 ≥400 计数；观察中断不表示远端任务失败 |
| `cagent_active` | 已开始但未结束的操作数，不是数据库中活动 Run 总数 |
| `cagent_duration_seconds_sum` | 已结束操作累计耗时，可结合 operations_total 求均值；当前不提供延迟分位数 |
| `cagent_capacity_rejections_total` | 容量闸门拒绝次数，含恢复跳过；不等于新运行失败数或唯一请求数 |

唯一标签 `operation` 只允许 `request/model/tool/storage/sse/recovery/observation/run/other`；不使用模型名、工具名、URL、用户、租户、Run ID、错误原文作标签。指标为当前进程累计值，重启归零。运维采集本身也经过请求指标中间件。

请求、后台 Run、模型、Catalog 工具执行、MongoDB 命令、SSE、恢复扫描和后台观察均接入。Span 只保存随机关联 ID、父 ID、固定操作名、时间、耗时和失败布尔值。后台运行仅复制请求的观测关联，生命周期继续取自服务上下文；HTTP 断连不会取消 Run。MongoDB 监控不解析或输出命令、查询、回复和驱动错误原文。恢复扫描从新 trace 开始，存储命令为其子 span。

这是有界的进程内追踪实现，不是 OTLP 导出器，也不承诺跨服务或跨重启完整追踪。环形缓存覆盖最旧记录；活跃长 span 在结束前不会进入历史缓存，但会出现在 active 指标中。没有异步导出 goroutine、无界 span 队列或单独工具 Worker。需要长期留存时由运维采集指标和诊断快照，不能用它们代替数据库审计事实。

## 日志敏感字段

P10.2 将 P1.4 暂缓的处理补齐：保留 Logrus 默认实例、显式关联与 Lumberjack 轮转，formatter 在副本上只允许固定关联/操作字段；丢弃 tenant/user、凭据、提示词、请求体、响应体及未知嵌套字段。error 只保留稳定类别，未知错误为 `internal_error`，不展开原因链。受信字段只接受有界字符串和整数，不执行任意 Stringer。

消息文本必须来自代码中的固定事件说明，禁止把提示词、工具返回值或任意错误拼接为 Message。formatter 不识别自然语言中的任意秘密，也不能保护绕过该 logger 的第三方输出；本地扩展应遵守同样规则。现有生产日志调用已核对，包含的消息均为固定文本。日志保留与磁盘配额由部署者负责，建议 `CAGENT_LOG_ROLL` 使用正值；0 的“不限备份数”旧约定仍保留。

## 数据保留与清理责任

默认采用保守策略：**数据库恢复事实永久保留，不创建 TTL 索引，不自动删除活动数据**。时间不是任务失败或结果已消费的证据。P10.2 明确保留边界，不增加未经授权的自动资源删除任务。

| 数据 | 默认与允许的清理边界 | 责任 |
| --- | --- | --- |
| 原始 messages、sessions、context_snapshots | 原始历史保留；摘要是派生信息，不能以摘要覆盖为理由删除原文 | 应用数据管理员按会话归档/删除政策处理，当前无自动会话删除接口 |
| events | 默认不清理。确需过期时仅使用内部 `Recovery.PruneEvents`，原子删除连续前缀并推进 PrunedThrough；旧游标明确返回过期 | 管理端指定作用域、Run 和经确认的重放截止水位；部署者承诺的 SSE 重连窗口内不得清理 |
| tasks、pending deliveries、checkpoints、leases、runs | 活动 Run、未完成/暂停 Task、pending 交付、待恢复检查点均不按年龄删除。终态 Run 仍可能有迟到任务 | 保留至全部任务终态、全部交付 applied/discarded、无恢复需求，并结束审计/重放窗口后才能整体归档；当前无自动清理执行器 |
| mutation_receipts、Run 幂等键/输入摘要 | 默认永久保留，不提前 TTL，避免未知提交结果重试失去幂等事实 | 重试承诺窗口和会话归档一起结束后才允许整体清理；不能单独清理回执再继续接受旧操作重试 |
| artifact | 默认不装配后端，大结果明确失败，不伪装成截断成功。`ArtifactWriter.Put` 成功必须代表完整内容已持久保存 | 自定义后端负责 Scope 下载授权、加密、配额、孤儿回收与对象删除；保留时间不得短于引用它的历史、任务、检查点和恢复/审计窗口 |
| 观测与日志 | span 最多 256 条、指标重启归零、日志文件按配置轮转 | 运维采集与磁盘保留策略独立管理，不影响业务恢复 |

清理过程必须先确认没有活跃租约、恢复扫描或迟到结果可能再次引用目标；单条文档 TTL 无法原子维护这些关系，因此不得自行添加。当前没有配置数字型“任务最长寿命”或自动 artifact GC，避免给出与实际恢复窗口不一致的承诺。后续接入 artifact 后端或有限保留期限时，必须先增加有授权和一致性保护的管理流程及真实集成测试。

## 验证

新增测试覆盖闸门并发拒绝/取消/幂等释放、配置加载与边界、真实 MongoDB 落库前拒绝及满载幂等重放、取消/关闭释放、观察过载不伪造终态、共享模型闸门及流提前关闭、SSE 过载/断连/重连、运维接口免认证访问、低基数指标、有限 span 缓存、父子关联、日志脱敏、MongoDB 命令完成/失败配对。原有慢 TCP 消费者、工具结果/artifact 限制、长任务暂停恢复、事件清理水位和重放测试继续执行。

本地验收使用项目内 MongoDB 8.0.32 临时单节点副本集、本地 OpenAI 协议服务和真实 ADK；外部模型/MCP/A2A、多节点部署故障、容量压测目标及真实 artifact 后端未配置，不据此宣称外部验收完成。复现命令与结果见 [实施进度](implementation-plan.md)。
